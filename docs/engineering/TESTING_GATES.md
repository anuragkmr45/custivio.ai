# Testing Gates

This file defines mandatory tests after every feature and phase.

## Universal commands

Run after every task:

```bash
pnpm check
pnpm build
RUN_DB_TESTS=1 pnpm test
```

Run when DB/schema changes:

```bash
pnpm db:generate
pnpm db:migrate
pnpm db:seed
```

Run when UI flows change:

```bash
pnpm test:e2e
```

If E2E is not set up yet, create the E2E test plan and do manual QA.

## Gate A — Code quality

Must pass:

- TypeScript typecheck
- ESLint
- format check
- forbidden dependency check
- no architecture boundary violations

## Gate B — Database

Required if DB changed:

- migration generated
- migration applies to empty database
- migration applies to existing dev database
- seed is idempotent
- repository tests pass
- tenant isolation tested
- uniqueness/foreign-key constraints tested

## Gate C — Backend/API

Required if server action/route/service changed:

- input validation tested
- permission check tested
- tenant check tested
- audit log tested
- typed error tested
- success path tested
- failure path tested

## Gate D — Storage/MinIO

Required if attachments/import/export changed:

- upload works
- metadata saved
- download permission checked
- delete/soft delete works
- unsafe filename handled
- object key generated by storage package only
- file size/type limits tested

## Gate E — Valkey/cache/job

Required if cache/locks/rate limits/jobs changed:

- Valkey connection tested
- lock acquisition/release tested
- idempotency tested
- rate limit tested
- retry behavior tested

## Gate F — UI

Required if UI changed:

- empty state
- loading state
- error state
- success state
- validation message
- responsive layout
- keyboard navigation where applicable
- business-friendly labels
- no raw technical errors shown

## Gate G — Product Manager UAT

Every feature note must answer:

1. What business user does this help?
2. What is the normal happy path?
3. What happens when the user makes a mistake?
4. What confirmation/success does the user see?
5. What report/history/audit proves it happened?
6. Is the workflow understandable without developer support?

## Gate H — Regression

Before marking a phase complete:

- run all universal commands
- run DB tests
- run available E2E tests
- manually verify key workflows touched by phase
- update `PROJECT_PROGRESS.md`
